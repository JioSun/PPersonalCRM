# Проверки этапа 2.4 (до изменения статусов)

## Изолированное окружение

Из корня проекта в PowerShell:

```powershell
docker compose -f compose.test.yaml up -d --wait
$env:CRM_TEST_SERVICES = '1'
.venv/Scripts/python.exe -m pytest
```

Используются только тестовые сервисы: PostgreSQL `localhost:55432/personalcrm_test`
и Redis `localhost:56379/5`. Фикстуры проверяют адреса до очистки данных.
Пароль в compose — публичный тестовый, не для рабочего окружения.
PostgreSQL хранит данные в tmpfs, рабочие тома не подключены.
Тесты применяют миграции, очищают тестовые таблицы и Redis; тест миграции
откатывает только последнюю ревизию и снова применяет её. Параллельный запуск
нескольких наборов тестов на этих сервисах не поддерживается.

Без `CRM_TEST_SERVICES=1` интеграционные тесты пропускаются, проверки схем
выполняются без подключения к сервисам. Пропуск не означает успешную интеграционную проверку.

После работы:

```powershell
docker compose -f compose.test.yaml down
Remove-Item Env:CRM_TEST_SERVICES -ErrorAction SilentlyContinue
```

## Покрытие

- POST → GET всех входных полей сделки и счёта.
- PATCH → GET, сохранность остальных полей и очистка nullable-полей.
- Отклонённый PATCH не меняет запись.
- Каждый HTTP-запрос использует новую SQLAlchemy-сессию.
- Прямые запросы в БД проверяют CHECK, NOT NULL и длины строк без Pydantic.
- Миграции применяются к пустой БД; последняя миграция проверяется в обе стороны.
- Несовместимые старые данные отклоняются до изменения схемы, без исправления наугад.

`deadline` сделки преобразуется в дату UTC. При откате восстанавливается полночь UTC;
утраченное время суток восстановить невозможно. CHECK с trim отсекает обычные
пробелы; полную нормализацию пробельных символов на входе выполняет Pydantic.

Миграция ec2cc5f4aa73 заменяет enum invoice_status на
draft / issued / paid / cancelled только при пустой таблице invoices.
При наличии счетов upgrade и downgrade останавливаются без удаления данных.
Перенос старых счетов намеренно вне текущего задания.
Исправленный файл уже применённой ревизии не запускается повторно автоматически:
проверяйте полную цепочку на новой тестовой БД.

Тесты test_overdue.py проверяют четыре статуса, вчера/сегодня/завтра,
JSON-сериализацию и пересчёт при смене дня UTC. Тест roundtrip проверяет
имя и значения PostgreSQL enum после отката и повторного применения.
Операции выставления/оплаты и исправление списков/сводки относятся к этапу 3.

Проверка 5 октября 2026: полный прогон на выделенных PostgreSQL/Redis —
173 теста прошли, включая замену enum и откат миграций. Пул соединений
создаётся отдельно для каждого теста: после DDL не переиспользуются
устаревшие планы asyncpg. Пункт 2.4 закрыт в согласованных границах
(пустая БД, без переноса старых счетов).
