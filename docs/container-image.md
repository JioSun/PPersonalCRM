# Образ PersonalCRM — приёмка 4.2

Проверено 25 октября 2026. Dockerfile подготовлен совместно с ассистентом;
самостоятельное владение всеми механизмами Linux этой проверкой не утверждается.

## Версии и обновления

Базовый образ: `python:3.12-slim`. Тег удерживает ветку Python 3.12 и slim-вариант,
но остаётся изменяемым: он не фиксирует точный patch-релиз Python, выпуск Debian
или digest. Побитовая воспроизводимость не заявляется. Для этой демонстрационной
версии сохраняем этот выбор. Обновления базы получаем отдельной плановой сборкой
с `--pull`; после обновления проверяем запуск, миграции и регрессию. При неожиданной
смене поведения сравниваем digest/ОС, прежде чем менять приложение.

uv закреплён на `0.11.29`. Python-зависимости устанавливаются из `uv.lock` с
`--frozen`; обновление зависимостей и lock — отдельное осознанное изменение.
При запуске `--no-sync` исключает повторную синхронизацию окружения.

## Сборка и запуск

Во время сборки root устанавливает зависимости с кэшем `/root/.cache/uv`.
После установки создаётся отдельный каталог `/home/app/.cache/uv`, принадлежащий
app. Только затем выполняется `USER app`. Создание файлов root после раннего
chown было причиной отказа в sdists-v9; настройка runtime-кэша перенесена вниз.
Код и установленное окружение остаются в `/app`, принадлежащем root.

Compose `command` заменяет Dockerfile CMD; параметры команды одного сервиса
не распространяются автоматически на другой. Доступ к кэшу проверен без
`--no-cache`, поэтому корректность больше не зависит от этого обходного флага.

## Подтверждённые проверки

- `docker build -t personalcrm-stage42-cache-check .` завершился успешно.
  Сборка использовала кэш слоёв; полностью холодная загрузка зависимостей не проверялась.
- Отдельный контейнер с `--network none`, без env-файла и volumes:
  UID/GID 10001 (app), `uv run --no-sync alembic --version` и импорт FastAPI успешны.
  Созданный uv каталог sdists-v9 принадлежит app.
- В этом образе отсутствуют `/app/.env`, `/app/.git` и Windows-окружение
  `/app/.venv/Scripts`; Linux-окружение устанавливается при сборке. Проверены
  соответствующие исключения .dockerignore. Это не аудит всех возможных секретов
  в исходниках или истории Git.
- TestClient внутри изолированного контейнера: GET `/` — 200,
  GET `/pay/check-invoice/check-token` — 200 и HTML. Redis подменён только для
  проверки упаковки/маршрутов. Email-шаблон присутствует. Это не браузерная
  проверка оплаты и не проверка реальных зависимостей.
- Пользователь подтвердил работающий запуск после пересборки Compose и
  исправления ошибки кэша. Ассистент рабочую БД не изменял.
- Системные библиотеки PDF в Dockerfile отсутствуют. AI/SMTP не вызывались.
